    Loadable Table Mixins¶

    Infrastructure for staged, file-based ingestion into ORM tables.

    Supports: - staged file loading into backend-specific staging tables - bulk staging sinks per backend: PostgreSQL COPY, DuckDB insert from Arrow, SQLite executemany - backend-aware merge strategies - Arrow-based file readers (delimited text and Parquet) - index handling during merge

    FileLoadableTableInterface¶

    Bases: ORMTableBase

    Mixin for ORM tables that load from files through a staging table.

    A file is read in batches by a reader, converted under a conversion policy, written to a staging table by the backend's bulk sink, and merged into the target table. It supports: - dialect-aware staging table creation - delimited text and Parquet files, and other formats through readers - configurable merge strategies - explicit staging table lifecycle management

    The class is designed for controlled ingestion pipelines and does not attempt to provide concurrency guarantees.

    		 None

    manage_indices(session, index_strategy='auto', *, backend) classmethod ¶

    Manage non-primary-key indexes around a staged merge.

    index_strategy may be "auto", "drop_rebuild", or "keep". The backend decides what "auto" means. At the moment SQLite keeps indexes by default, while PostgreSQL drops and rebuilds them.

    Raises:

    Type Description
    IngestError

    An index could not be rebuilt after a merge that was committed.

    validate_foreign_keys(session, *, staging_schema_tag=None, resolved=None, physical_schemas=None) classmethod ¶

    Raise if any row references a row that does not exist.

    Loads relax foreign keys during the merge on PostgreSQL and SQLite, so a row loaded before the row it references is accepted. Call this once every table is loaded to verify referential integrity, whatever the load order. DuckDB enforces most of its keys itself, so only the keys it cannot enforce are checked.
